* Python Data Model
It is the API that are used to make the objects play well with the most idiomatic language features (*Pythonic*).

You can think of the data model as a description of Python as a framework. It formalizes the interfaces of the building blocks of the language itself

#+BEGIN_QUOTE
*Google NotebookLM*
O modelo de Dados Python é a API que se utiliza para que os objetos definidos pelo usuário interajam bem com os recurso idiomáticos da linguagem
#+END_QUOTE

When using a framework, we spend a lot of time coding methods that are called by the framework. The same happens when we leverage the Python Data Model to build new classes. The Python interpreter invokes special methods to perform basic object operations, often triggered by special syntax. The special method names are always written with leading and trailing double underscores

#+BEGIN_QUOTE
*Google NotebookLM*
A essência de trabalhar com o Modelo de Dados é implementar métodos especiais (também chamados de *dunder methods*). O interpretador Python invoca esses métodos especiais para executar operações básicas, que são frequentemente acionadas por sintaxes especiais
#+END_QUOTE

We implement special methods when we want our objects to support and interact with fundamental language constructs such as Collections, Attribute Access, Iteration (including asynchronous), Operator overloading, Function and method invocation, String representation and formatting, Asynchronous programming, Object creation and destruction, Managed contexts

#+BEGIN_QUOTE
*Google NotebookLM*
Ao implementar métodos especiais, seus objetos se comportam como os tipos embutidos, permitindo um estilo de codificação expressivo que é considerado Pythonic. Duas vantagens principais são:

1. *Nomes Padrão:* Os usuários das suas classes não precisam memorizar nomes de métodos arbitrários para operações padrão
2. *Aproveitamento da Biblioteca Padrão:* Torna-se mais fácil tirar proveito da rica biblioteca padrão do Python, evitando a reinvenção da roda
#+END_QUOTE

#+begin_quote
*NotebookLM*
*"O que é o Modelo de Dados do Python? Porque usar e como usar corretamente? Pergunto pois sempre programei em python mas raramente ou nunca uso dunder methods, sempre criei funções e classes da maneira convencional."*

O modelo de dados do Python é o alicerce que permite que classes personalizadas se integrem perfeitamente com recursos nativos da linguagem, algo que se torna muito mais relevante ao construir bibliotecas ou frameworks

A chave para a consistência e o comportamento uniforme de todos os tipos de objetos em Python reside nos métodos especiais

Ao implementar dunder methods (métodos especiais), você permite que seus objetos se comportem como os tipos internos do Python, o que leva a um estilo de codificação expressivo que a comunidade considera Pythonic

Usar esses métodos e o PDM (Python Data Model) traz vantagens significativas:
1. Consistência e Previsibilidade
2. APIs instuitivas
3. Aproveitamento da Biblioteca Padrão
4. Funcionalidades Nativas

O uso correto do PDM e dos métodos especiais segue convenções rígidas estabelecidas pelo desing da linguagem:

1. Chamada de métodos
   - Não chame diretamente: Os métodos especiais são feitos para serem chamados pelo interpretador Python e não por você. Você não deve escrever ~my_object.__len__()~. Em vez disso, você escreve ~len(my_object)~ e o Python chama o método ~__len__~ que você implementou
     
   - Usar funções embutidas: Se precisar invocar um método especial, geralmente é melhor chamar a função embutida relacionada (ex: ~len, iter, str, abs~)

   - A exceção comum: O único método especial que frequentemente é chamado diretamente pelo código do usuário é o ~__init__~, geralmente para invocar o inicializador da superclasse

2. Implementação de Operadores:
   Ao implementar operadores como ~+, *, -~ deve-se seguir o príncipio de sempre retornar um novo objeto e não modificar o receptor ~self~
   - Infix Operators (ex: ~__add__~): Devem criar e retornar novos objetos, e não tocar nos operandos

   - Inflexibilidade de Tipo (NotImplemented): Se um método especial de operador infix não conseguir retornar um resultado válido devido a incompatibilidade de tipo (por exemplo, tentando somar seu objeto ~Vector~ com uma string), ele deve retornar o valor singleton especial ~NotImplemented~ e não levantar um ~TypeError~. Retornar um ~NotImplemented~ permite que o interpretador tente a versão reversa do operador (ex: ~__radd__~)
#+end_quote
